# Errata: YNM 1.2.0 Publication Timestamp and Ancestry Evidence

## What was observed

- The candidate 1.2.0 evidence set recorded a verification basis timestamp at `2026-08-19T16:11:39Z`.
- Later review notes included timestamps such as `2026-08-19T18:00:00Z`, `2026-08-19T19:00:00Z`, and `2026-08-19T19:15:00Z`.
- The same review direction also referenced Git ancestry checks through `v1.2.0` objects.

## What is known

1. `state/releases/1.2.0/baseline-hashes.yaml`, `state/releases/1.2.0/final-assessment.yaml`, and `state/releases/1.2.0/assessment.yaml` were used as 1.2.0 release evidence.
2. `v1.2.0` remains the canonical tag for that release.
3. No replacement of historical release files was performed when this correction was introduced.

## What is not known

- Whether the original later timestamps reflect timezone conversion, delayed publication, or external workflow behavior.
- Whether the original verification-basis record represented the exact checked material at the time it was reported.

## What was corrected in 1.3.0 candidate evidence

- Added a formal correction record under `state/releases/1.3.0/corrections/1.2.0-publication.yaml`.
- Added provenance explanation in `docs/errata/1.2.0-publication.md`.
- Preserved historical 1.2.0 files and `v1.2.0` tag integrity.
- Preserved `YNM-VAL-001` as unresolved because independent implementation validation remains unavailable.

## Why this remains unresolved

The historical causality remains a candidate-only uncertainty. This errata does not infer a technical defect in the core YNM assessment and does not claim that evidence was wrong, only that timestamp causality was not conclusively established.

The candidate release remains self-contained and append-only while keeping the original 1.2.0 artifacts readable.
