# Capability-Adaptive Execution

Capability changes execution strategy, not truth. Use as much executor capability as helps the bounded question, but never require more than necessary. When the requested scope cannot be reviewed responsibly, change scope, partitioning, sequencing, or executor; never lower evidentiary standards.

## Invariants

1. **Semantic stability:** capability never changes YES, NO, or MAYBE.
2. **Scope before standards:** reduce or partition scope before reducing rigor; rigor is not reducible.
3. **No false coverage:** unreviewed evidence is never represented as reviewed.
4. **No capability confabulation:** discover capabilities or mark them unknown.
5. **Exhaustion is not convergence:** executor limits produce PARTIAL or BLOCKED, not methodological convergence.
6. **Provenance survives decomposition:** every summary and aggregate retains paths to original evidence.
7. **Specialization preserves contracts:** all executors use common YNM records and semantics.
8. **Capability grants no authority:** analytical reach does not expand decision or mutation permission.

## Select a strategy

Compare the [Execution Context](../contracts/execution-context.md) with project complexity and requested scope.

- `CONSTRAINED`: use one loop and bounded scope at a time, controlled evidence windows, small active finding sets, sequential transitions, explicit checkpoints, frequent persistence or emitted state, deterministic handoffs, and explicit unresolved dependencies.
- `STANDARD`: use ordinary focal-loop execution, moderate safe parallelism, cross-loop correlation, and persistent reconciliation where available.
- `EXTENDED`: permit broader initial scope, independent or parallel focal reviews, richer history comparison, contradiction passes, and comprehensive dependency mapping when useful.

Extended capacity does not justify extra ceremony, combined responsibilities, unsupported assumptions, or greater authority. A well-bounded constrained review may be more reliable than uncontrolled extended execution.

## Adapt in order

When fit is inadequate: reduce scope; partition by artifact, component, subsystem, project, or portfolio; retrieve evidence selectively; run loops sequentially; preserve intermediate state; delegate to a suitable specialist when available; defer unsupported conclusions; then return PARTIAL or BLOCKED if responsible continuation is impossible.

For large projects, synthesize progressively from typed evidence to local findings, subsystem conclusions, cross-subsystem relationships, then project conclusions. Project-level claims identify unreviewed partitions. Controlled evidence windows distinguish “not observed because excluded” from “observed and absent.”

Compression preserves finding ID, proposition, disposition and reason, critical evidence references, conflicts, dependencies, revisit conditions, and authorization. Summaries are indexes to evidence, not replacement evidence when originals remain accessible.

## Delegate and continue

Assign loops by demonstrated capability rather than assuming one executor is equally suitable for code, architecture, adoption, and state reconciliation. Delegation is optional. With one executor, use frozen assessments and separate analytical passes; record `SEPARATE_ROLE`, not false independent evaluation.

A capability-aware finding budget limits only the active working set. Queue, persist, or emit overflow; never discard findings. If context, tools, or budget become inadequate, stop expansion, preserve completed evidence, partition remaining scope, and continue or escalate. Run Receipts identify reviewed and unreviewed scope.

Rediscover material capabilities on later runs. Tool loss means prior evidence remains historical but was not rerun. A more capable executor appends new evidence and interpretation; it does not silently replace earlier review history. Humans are executors under the same rules.

In stateless mode, emit complete intermediate findings, evidence references, dependencies, continuation scope, and Run Receipts. Do not rely on implicit memory between invocations.
