# Documentation Project Example

A documentation project has no executable product code. The Meta Loop returns `NOT_APPLICABLE` for Implementation after discovery, but selects Architecture, Adoption, and Maintenance.

- Architecture asks whether the information hierarchy and declared audience model are coherent.
- Adoption attempts representative reader tasks and finds that the publication is accessible but lacks a path from concepts to procedures.
- Maintenance compares references and identifies several links to retired source material.

The adoption proposition, “A new policy analyst can locate the procedure for submitting a revision,” receives NO from direct task evidence. The maintenance proposition, “All external references resolve to their intended current sources,” remains MAYBE because a required archive is temporarily unavailable. The MAYBE uses `EVIDENCE_REQUIRED` and a revisit condition tied to archive access.

No loop edits the documents in default review mode. A later remediation request may authorize specific documentation changes without authorizing unrelated restructuring.

A human-only reviewer records strong policy expertise, file access, and limited archive access; AI capabilities are absent rather than required. If the collection exceeds available time, the reviewer partitions by audience journey and emits intermediate receipts. The standards for YES, NO, and MAYBE remain unchanged.
